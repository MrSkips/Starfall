# Technical architecture and interface contracts (v00 draft)

## 1. Source of truth and sync
- **Revised (D-007 rev 2):** Studio is the live code surface (Claude edits through Studio MCP `multi_edit`). The place is saved as `place/StarfallForge.rbxlx`, and `tools/export_scripts.py` mirrors every script into `src/` for git history and review. Always export before committing.
- ChatGPT returns code as complete files in its RETURN block. Zack saves them (or pastes them to Claude), and Claude integrates them into `src/` and syncs.
- Map and greybox are generated by scripts in `tools/` (re-runnable and seeded), never placed by hand.
- Before v03, Zack saves the place as `place/StarfallForge.rbxl` and publishes it privately (DataStores need a published place with Studio API access turned on).

## 3. Server/client split
**Server (authoritative):** plot assignment, meteor schedule and spawn, mutation rolls, pickup and drop validation, carrying state and walk speed, machine processing, Stardust balance, purchases, persistence (v03), analytics events.
**Client (presentation only):** HUD, arrows and beams to meteors, screen shake, local particles and sounds, shop UI requests.
Core actions use **server-side ProximityPrompt.Triggered**, so v01 needs no client-to-server remotes for gameplay. Every remote added later is validated for type, range, rate (≤ 5/s per player), and ownership.

## 4. Module APIs (contract v1, owner Claude)
```lua
-- Config (ReplicatedStorage.Shared.Config): plain table, no functions
Config.Meteor = { SpawnIntervalSec=20, MaxLive=12, DespawnSec=60, BaseValue=15,
  Mutations = { {Id="Normal",Weight=70,Mult=1}, {Id="Molten",Weight=18,Mult=2},
    {Id="Frozen",Weight=8,Mult=3}, {Id="Charged",Weight=3.5,Mult=5}, {Id="Cosmic",Weight=0.5,Mult=12} } }
Config.Carry  = { WalkSpeed=11, AllowJump=false, PickupRange=10 }
Config.Shower = { IntervalSec=360, Count=15, StarheartCarriers=2 }
Config.Machines = { {Id="Crusher",Cost=0,ProcessSec=4,Mult=1}, ... }
Config.Debug  = { DropOnPlot=false }  -- A/B for fallback F

-- PlotService
PlotService.GetPlot(player): Model?          PlotService.GetOwner(plot): Player?
PlotService.PlotAssigned: BindableEvent(player, plot)

-- EconomyService
EconomyService.Get(player): number
EconomyService.Add(player, amount: number, reason: string)
EconomyService.TrySpend(player, amount: number, reason: string): boolean

-- MeteorService
MeteorService.Spawn(opts: {position: Vector3?, mutation: string?, isStarheart: boolean?}): Model
MeteorService.StartShower()
-- chunk attributes: MeteorId (string), Mutation (string), Value (number), Carriers (number)

-- CarryService
CarryService.IsCarrying(player): boolean
CarryService.Pickup(player, chunk): boolean   -- validates range, not already carrying
CarryService.Drop(player): Model?
CarryService.Deposit(player, machine): boolean -- must be the player's own plot

-- MachineService
MachineService.Enqueue(plot, chunkValue: number, mutation: string)
-- ticks at 1 Hz server-side and pays EconomyService.Add(owner, ...)

-- PurchaseService
-- in-world pads: attributes ItemId, Cost, Requires (ItemId?) ; touch → TrySpend → reveal model
```
Tags (CollectionService): `MeteorChunk`, `Machine`, `PurchasePad`, `Plot`.
Interface changes go through `docs/DECISIONS.md` before any dependent work.

## 5. Persistence (v03)
Profile schema `{ v=1, stardust, purchases={}, rebirths, codex={}, lastOnline, dailyClaimAt }`. Session locking (`UpdateAsync` with lock timestamp), retries with backoff, autosave every 120 s, save on leave and `BindToClose`, and migration functions keyed by `v`. Use a separate test DataStore name in Studio.

## 6. Performance budgets (all **provisional**, measured from v02)
| Budget | Target | How we measure |
|---|---|---|
| Client frame time on mid-range phone | ≤ 16.7 ms (60 fps), never above 33 ms in a shower | MicroProfiler or Studio device emulation, plus a real phone test by Zack |
| Server heartbeat with 8 players during a shower | ≥ 55 Hz | Studio multi-client test, `Stats` |
| Live meteor chunks | ≤ 12 normal, ≤ 28 in a shower | Config cap |
| Triangles per plot (fully built) | ≤ 15k | SceneAnalysis skill |
| Particle emitters active | ≤ 40 on screen, halved with reduced effects | count in test |
| Join to first meteor visible | ≤ 10 s on Wi-Fi | stopwatch in playtest |
Settings: StreamingEnabled on, plots as atomic models, collision boxes separate from decorative meshes.

## 7. Asset pipeline (lowest complexity first)
| Asset family | Pipeline | Owner |
|---|---|---|
| Greybox map, plots, ramps | `tools/build_greybox.luau` (procedural Parts, seeded) through `execute_luau` | Claude |
| Terrain crater | Luau Terrain API (FillBall/FillBlock), seeded | Claude |
| Meteor chunks (5 mutations) | 1 base rock from `generate_mesh` (≤ 2k tris) plus per-mutation material, color, and particles | Claude, with ChatGPT concept |
| Machines (4 tiers) | `generate_procedural_model` / `generate_mesh` with ChatGPT concept sheet as the brief, then a separate collision box | Claude, ChatGPT concepts |
| Materials | `generate_material` (MaterialVariants) from the art bible palette | Claude |
| Icons and UI art | ChatGPT image gen, uploaded by Zack (or `upload_image` by Claude if allowed) | ChatGPT |
| UI layout | Figma (if write access works), then native Roblox UI built by Claude | ChatGPT design, Claude build |
| Effects | ParticleEmitter, Beam, Trail with code-defined properties | Claude |
| Audio | Roblox licensed audio library (rights tracked) or procedural. No custom generation available | Claude picks, Zack approves |
| Thumbnail and icon | ChatGPT image gen from a *real* in-game screenshot composition | ChatGPT |
Every asset gets a row in `ASSET_MANIFEST.md`.
